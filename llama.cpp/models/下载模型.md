# 模型下载说明

> **本项目不再使用带 MTP 的模型。** 实测带 MTP 的同规格模型即使不开投机也**慢约 14%**
> （21.0 vs 23.7 t/s），开启 `--spec-type draft-mtp` 更慢（掉到 10.5 t/s）。
> 下面三个链接均来自 **`unsloth/Qwen3.6-35B-A3B-GGUF`（无 MTP 版仓）**，请勿再用
> 旧的 `...-MTP-GGUF` 仓库（那份是带 MTP 的）。

本仓库**不包含模型文件**（主模型 20.6 GB，太大）。**最省事的是让启动脚本自动下载**
（见第一节）；也可以按本文手动下载后放到**本目录**下。

下载完成后，本目录应该长这样：

```
llama.cpp\models\
├── Qwen3.6-35B-A3B-UD-Q4_K_M.gguf     ← 推荐（32GB 内存 / 16G*2，最多 64K 上下文）
├── Qwen3.6-35B-A3B-UD-IQ3_S.gguf      ← 小内存首选（16GB 内存，最多 64K）
├── mmproj-BF16.gguf                   ← 视觉投影（可选，不下载就退化为纯文本）
└── 下载模型.md                         ← 本说明
```

> **脚本会自动识别目录下的模型**，按 Q4_K_M → IQ3_S 的顺序挑**存在且可用**的那份，
> 都不在则由启动脚本引导下载（见第一节）。**不需要手动改脚本。**
> 另外，小于 1 GB 的文件会被判定为「损坏/不完整」并重新下载覆盖。

> **该下哪个？主要看内存**（内存决定装不装得下，显存只决定跑多快）：
> - **16 GB 内存** → `IQ3_S`，最多 **64K** 上下文（配 4 GB 以上显存会更宽松）
> - **32 GB 内存（16G×2 双通道）** → `Q4_K_M`，最多 **64K** 上下文
> - **32 GB 内存 + 8 G 以上显存** → `Q4_K_M` 及以上，**64K 以上**上下文（96K / 128K）

---

## 一、最省事：让启动脚本自动下载（推荐）

**不用手动做任何事**。双击 `启动大模型_StartModel.bat`，脚本做完环境检查后会检查模型：
发现 `llama.cpp\models\` 下没有可用模型（或文件不完整）时，直接弹出选择菜单：

```
1   IQ3_S     ~12.74 GB    16G 内存设备首选，需 4G 以上显存
2   Q4_K_M    ~20.61 GB    推荐，32G 内存
0   退出（可稍后按 下载模型.md 手动下载）
```

- 输入 `1` 或 `2`（**直接回车 = 2**）；脚本会先报一次磁盘剩余空间做预检，确认后开下；
- 下载用系统自带 `curl`，**支持断点续传**：中断后再运行脚本会接着下，不会从头再来；
- 下完自动校验文件大小，与官方发布值一致才提示「下载完成，模型已就绪」，
  按回车直接进入档位选择；
- **已经有可用模型时这一步整段跳过**，不会打扰你。

> 只有**主模型**走这条自动通道；**mmproj 视觉投影需要手动下载**（见第二节）。
> 系统没有 `curl`（极老的 Win10）时，脚本会跳过下载引导并提示你按本文件手动下载。

## 三、下载方式（手动）

**浏览器**：直接点上面的链接即可。

**命令行**（支持断点续传，下载 20 GB 时强烈建议）：

```bat
curl -L -C - -o "Qwen3.6-35B-A3B-UD-Q4_K_M.gguf" ^
  "https://hf-mirror.com/unsloth/Qwen3.6-35B-A3B-GGUF/resolve/main/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf?download=true"
```

**huggingface-cli**（需要先 `pip install huggingface_hub`）：

```bat
set HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download unsloth/Qwen3.6-35B-A3B-GGUF ^
  Qwen3.6-35B-A3B-UD-Q4_K_M.gguf --local-dir .
```

## 四、下载完检查一下

大小对不对是最快的判断方式：

| 文件 | 精确字节数 |
|---|---|
| Qwen3.6-35B-A3B-UD-Q4_K_M.gguf | 22,134,528,992 |
| Qwen3.6-35B-A3B-UD-IQ3_S.gguf | 13,676,723,168 |
| mmproj-BF16.gguf | 902,822,624 |

也可以直接跑一次 `环境检查_EnvCheck.bat`，它会报出模型的实际大小并和预期值（约 20.6 GB）比对。

**确认是不是无 MTP 版**：跑
`python _维护脚本\gguf_inspect.py <模型文件>`，应看到 `--> MTP 头张量数: 0 （无）`。
若显示 4（含 `blk.*.nextn.*`），说明下成了带 MTP 的旧版，速度会慢约 14%。

## 五、换成 IQ3_S（16 GB 内存设备）

**不用改脚本** —— 把 `Qwen3.6-35B-A3B-UD-IQ3_S.gguf` 放进本目录就行：

| 目录里的情况 | 启动脚本用哪个 |
|---|---|
| 只有 IQ3_S | 自动用 IQ3_S，档位菜单显示 `Qwen3.6-35B-A3B-UD-IQ3_S（MoE，无 MTP，12.7 GB）` |
| 两个都有 | 优先用 Q4_K_M；想强制用 IQ3_S，把 Q4 那个文件移出目录即可 |

也可以直接让启动脚本帮你下 IQ3_S —— 没检测到模型时它会弹出选择菜单，输入 `1` 就是
IQ3_S（见第一节）。**不需要再用记事本去改 `启动大模型_StartModel.bat`。**

> IQ3_S 更小（12.74 GB），**16 GB 内存的设备首选**（32 GB 及以上当然也能跑）；代价是量化质量略降。
> 实测速度比 Q4_K_M 约快 5%。换模型后档位表里的速度/内存数值会有小幅变化，
> 建议重新用 `环境检查_EnvCheck.bat` 确认内存是否够用。
