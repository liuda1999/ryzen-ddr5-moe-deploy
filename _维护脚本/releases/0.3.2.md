## 0.3.2 — 修 CUDA 后端编译脚本卡死（补丁版）

> 本版只改一个维护脚本，**运行时代码、参数、档位与 0.3.1 完全一致**，不需要重新标定速度。
> 普通使用（纯 CPU，或按 README 直接取现成的 `ggml-cuda.dll`）**不受影响**；
> 只有"自己编译 CUDA 后端"这条路才会触发。

### 问题

`_维护脚本\build-cuda-backend.bat` 开头做编译器自检：

```
cl.exe 2>&1 | findstr /C:"Version"
```

`cl.exe` **不带参数时会去读标准输入**（它支持从 stdin 读源文件），
在批处理的管道环境里永远等不到 EOF，于是整个脚本**永久挂起**。
本机实测卡住 **12 分钟**，`cl.exe` 进程一直存活，直到手工结束才继续。

这个卡点很隐蔽：脚本没有任何报错输出，看起来像是在"慢慢编译"。

### 修复

```
cl.exe /? 2>&1 < nul | findstr /C:"Version"
```

- `/?` 让它打印版本信息后立即退出；
- `< nul` 显式切断标准输入，双保险。

### 验证

用修复后的脚本从零完整跑一遍（CUDA 12.8 + MSVC 14.44，arch 61）：

| 阶段 | 结果 |
|---|---|
| 编译器自检 | 立即输出 `Version 19.44.35225` |
| CUDA 自检 | `release 12.8, V12.8.61` |
| CMake 配置 | 通过 |
| 编译 | `[156/156] Linking CUDA shared module` |
| 产物 | `llama.cpp\build-cuda\bin\ggml-cuda.dll`（32 MB） |
| 总耗时 | **5 分 18 秒**，输出 `BUILD_OK` |

### 另外提一句

脚本要求 **CMake 与 Ninja 在 PATH**，而项目本身不带这两个工具、README 也没提。
本次只在提交说明里写明了这一点，**没有**加自动检测——如果需要，后续版本可以补一个"缺工具就明确报错"的前置检查。

### 升级建议

只替换 `_维护脚本\build-cuda-backend.bat` 即可，其余文件与 0.3.1 相同。
