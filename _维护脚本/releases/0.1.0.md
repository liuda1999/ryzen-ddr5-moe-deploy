## 首个发布版本

在 **AMD Ryzen + DDR5（开 EXPO）** 平台上，用**纯 CPU、不靠显卡**把 35B 级 MoE 大模型跑成开箱即用的本地服务。

这一版把「Ryzen + DDR5 内存带宽」这条工程主线上的全部细节固化下来：
编译哪些 CPU 指令集变体、内存要开 EXPO 到什么频率、线程给多少、上下文开多大、
内存够不够、密钥怎么给、局域网怎么开——都已调好并实测过。

> ### 关于模型：套件与模型是分离的
>
> 下面是**当前验证过的实例**，不是项目的定义。换模型只需替换 `.gguf` 并改脚本里一行 `MODEL` 变量。
>
> | 当前实例 | Qwen3.6-35B-A3B（MoE 架构，256 专家激活 8 个），Q4_K_XL 量化，21.28 GB |
> |---|---|
> | 选型逻辑 | MoE 每 token 只激活少量专家 → 算术强度低 → 瓶颈落在**内存带宽**上。同规格 MoE 模型同样适用 |
>
> 密集（非 MoE）模型每个 token 要读全部权重，纯 CPU 上会明显更慢。

---

### 为什么核心是内存带宽，而不是算力

MoE 解码时，每生成一个 token 真正参与计算的权重量很小，但权重必须从内存搬进 CPU。所以：

```
生成速度 ≈ 内存带宽 ÷ 每 token 需要读取的字节数
```

由此推出三个必须满足的前提：

1. **必须开 EXPO**。DDR5 默认跑 JEDEC 4800 MT/s，内存条额定频率更高，要靠 BIOS 开 EXPO 才能达到。
   本机内存条是 **DDR5-6000**，开启后实际运行 **6000 MT/s**，相比默认值 **+25% 理论带宽**。
2. **必须双通道**。只插一条，带宽腰斩，速度近乎腰斩。
3. **先查内存，再调参数**。内存频率的影响远大于线程数微调。

**自查方法**：任务管理器 → 性能 → 内存 → 右下角「速度」。显示 4800 就是没开 EXPO。

```powershell
Get-CimInstance Win32_PhysicalMemory |
  Select-Object DeviceLocator, Capacity, Speed, ConfiguredClockSpeed, PartNumber
```

### 硬件要求

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 **x64** |
| CPU | **AMD Ryzen 推荐**（本包在 Zen 5 上标定）；支持 AVX-512 更快，不支持会自动回退 AVX2 变体 |
| 内存 | **≥ 32 GB，强烈建议 2 条组双通道**（推荐 64 GB；默认档位需约 30 GB 可用） |
| 内存频率 | **建议开启 EXPO 跑到额定频率** |
| 磁盘 | Q4_K_XL 约 **25 GB**；IQ3_S 约 **17 GB** |
| 显卡 | **不需要** |
| 运行时 | **什么都不用装**（VC++ 运行库已随包附带，PowerShell / curl 系统自带） |

### 快速开始

1. 下载本页附件 **`ryzen-ddr5-moe-deploy-0.1.0-no-model.zip`**（约 10 MB），解压到任意目录
2. 按下方链接下载模型，放进 `llama.cpp\models\` 目录
3. 双击 **`启动大模型.bat`** —— 选档位（回车=实用档）、选用不用深度思考（回车=关闭），约 15\~30 秒后启动成功

> 同一个脚本再运行一次就是**关闭服务**。想确认在不在：`启动大模型.bat status`。

### 本版内容

- **llama.cpp 编译产物**：官方 `ggml-org/llama.cpp`（0.6.0-dev）编译，
  含 **9 个 CPU 指令集变体**（运行时自动择优）+ VC++ 运行时 DLL，免安装
- **`启动大模型.bat`**：二合一开关，未运行则启动、已运行则关闭；
  内置 9 项环境与安全检查，按实际可用内存预检档位可行性；
  就绪判定基于 `/health` 轮询（避免「端口一监听就报成功」的假成功）；
  服务**无窗口静默运行**；首次启动自动生成 API 密钥并复制到剪贴板
- **`环境检查.bat`**：10 项环境与安全体检
- **`开放局域网端口.bat`** / **`重新编译.bat`**
- **中文文档**：README、使用说明、参数阶梯手册、部署说明、验收报告、分发包清单
- **实测档位数据**（12 个测试点）

### 实测性能（Ryzen 9 9950X，64 GB DDR5-6000 EXPO，双通道）

| 档位 | 上下文 | 线程 | 生成速度 | 约需内存 |
|---|---|---|---|---|
| 1 极速档 | 12K | 24 | 13.28 t/s | 28 GB |
| **2 实用档（默认）** | **16K** | **24** | **12.73 t/s** | **30 GB** |
| 3 长文档档 | 24K | 24 | 11.82 t/s | 34 GB |
| 4 超长档 | 32K | 24 | 9.95 t/s | 38 GB |
| 5 极限档 | 64K | 28 | 4.28 t/s | 55 GB |

三条件测规律：

1. **24 线程在所有档位都比 28 线程快** —— 带宽已打满，多出的线程只是在抢内存总线
2. **prefill（读提示）约 70 token/秒封顶**，与线程数、批大小基本无关
3. **速度取决于实际填充的上下文长度**，不是分配的 `-c` 值（短提示可达 16.06 t/s）

> 换 CPU 平台**无需重新编译**，但档位速度表与线程数需按新 CPU 重定。
> 详见仓库内《参数阶梯手册.md》的「平台声明」。

### 安全提示

服务默认绑定 `0.0.0.0` 且启用了 API 密钥鉴权。要开放给局域网其它设备，
需以管理员身份运行一次 `开放局域网端口.bat` 放行防火墙端口。

放行后，**同网段任何拿到密钥的设备**都能占用你的 CPU 与内存做推理（默认档位单次约 30 GB）。
在咖啡厅、酒店等不可信 Wi-Fi 下，建议把 `启动大模型.bat` 里的
`set "HOST=0.0.0.0"` 改回 `set "HOST=127.0.0.1"` 后重启。
