## 0.3.7 — 8 GB 显存实测调优：生成 43.5 t/s、读提示 613 t/s

> 本版重做了 **8 GB 显存档**的参数：从「专家只放 1 层」改为「按显存把专家层用到满」，
> 并修掉一个一直存在的隐性损失（mmap 懒加载）。3\~4 GB 的纯 CPU 卸专家路线**未改**。
> 12 / 14 / 16 GB 三档按同一张参数表线性外推（**本机无对应显卡，未实测**）。

### 实测平台

| 项 | 值 |
|---|---|
| 显卡 | RTX 2070 8 GB（PCIe 3.0 x16） |
| CPU / 内存 | Ryzen 9 9950X（16C/32T）/ DDR5-6000 64 GB |
| 模型 | Qwen3.6-35B-A3B UD-Q4_K_M（40 层，256 选 8，20.6 GB） |
| 档位 | T4 长文档档 96K，q8_0 KV，视觉塔走系统内存 |

### 三条硬指标的验收结果

| 指标 | 要求 | 实测（96K 档） |
|---|---|---|
| CPU 占用 | 24 线程尽可能跑满 | **23.7 / 24 核**（系统 81.8%，96.6% 的秒数 ≥70%） |
| 显存占用 | 7 GB 多一点 | **7634 / 8192 MiB**（余 558 MiB） |
| Token 生成 | > 40 t/s | **43.5 t/s**（长生成 58 s，2515 token） |

附：PP4K **612.9 t/s**、PP16K **555.5 t/s**；64K 档同口径复测 43.2 t/s / 621.2 / 564.1。

### 主要变更

1. **专家层上限 1/2/3 → 8/12/14/16**（`GPU_EXPERT_CAP_T1/T2/T3B/T3`，新增 14G 分带）。
   8G/96K 在 512 MiB 余量底线下自动落 7 层，decode 由 40 → 43.5 t/s。
2. **`--load-mode none`**：启动时把 20.6 GB 权重全量读进内存，拿回 CUDA pinned host 内存与
   repack 内核，并消除「首轮生成现场缺页」。PP4K +12%、首句 decode +25%。
   代价是启动真读盘（热缓存 7\~9 s，冷盘 60\~120 s），`READY_TIMEOUT` 已提到 480 s。
3. **`-ub 1024 → 2048`（7 GB 以上）**：prefill 每个 ubatch 都要把 17.7 GiB 专家张量搬一遍 PCIe，
   ub 翻倍 = 搬运次数减半。PP4K +35%、PP16K +40%，decode 不变。
   compute 缓冲随之 660 → 914 MiB，`GPU_FIXED_MIB` 在 8G+ 带改为 900。
4. **线程口径固定 12 核 / 24 线程**：16 线程实测快 3.5%（47.0 vs 45.4），但本项目把 CPU 当作
   推理的一部分，24 线程让 CPU 占用从 15.8 核顶到 23.7 核。
5. **16 GB 档上下文 160K → 192K**：16 GB 预算本还剩约 4 GB，换上下文更划算
   （16 层专家后仍余 3522 MiB，预测峰值约 12.9 GB）。
6. **新增三个性能开关常量**：`GPU_LOADMODE` / `GPU_OPOFFLOAD` / `GPU_MOE_CACHE_MIB`，
   启动横幅会打印「性能开关」一行。后两者默认 `on` / `0`——实测关闭 op-offload 会让
   PP4K 从 378 掉到 332；专家 LRU 缓存是负收益（decode 掉 8\~15%）。
7. **新增监测脚本**：`_维护脚本/bench_8g_matrix.py`（A/B/C/D/U 共 17 组对照台架）、
   `_维护脚本/verify_final_8g.py`（typeperf 每秒采样 + 原始 CSV 的验收脚本）、
   `_维护脚本/verify_cpu.py`、`_维护脚本/start_service.py`。
8. 项目交接文档（含本机路径、密钥位置、内网地址）**不再随仓库公开**，仅本地保留。

### 为什么不「让 CPU 在 prefill 也满载」

prefill 时 CPU 只有 2\~4 核，原因是 `--op-offload` 把 MoE 整块交给了显卡
（batch ≥ 32 即判定卸载），CPU 只剩注意力与非专家层。实测把它抢回 CPU：
prefill 阶段 CPU 升到 23.9 核，但 **PP4K 从 378.6 掉到 332.2 t/s**，decode 也无收益。
所以 CPU 空转不是浪费，是显卡在干活；真正的原则是**两边各干自己快的活**。

### 升级建议

替换 `启动大模型_StartModel.bat` 与整个 `_维护脚本\` 目录即可，其余文件不变；
关键参数都在 bat 顶部的常量区（`GPU_LOADMODE` / `GPU_BAND_HIGH_UB` / `GPU_EXPERT_CAP_*`）。
8 GB 卡想退回旧行为：`GPU_LOADMODE=auto` + `GPU_EXPERT_CAP_T1=1`，重跑生成器。

本包**不含模型与 `ggml-cuda.dll`**：模型按 README 的下载指引自取；
CUDA 后端按 `_维护脚本\build-cuda-backend.bat` 自编，或直接用官方预编译包。
