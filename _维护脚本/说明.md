# _维护脚本 目录说明

这里放的是**运维 / 开发用**的辅助脚本。日常使用完全不需要碰——日常只需要双击根目录的 `启动大模型.bat`。

---

## 一、脚本生成器（改启动脚本时用）

| 文件 | 作用 |
| --- | --- |
| `gen_toggle.py` | 生成 `..\启动大模型.bat`（二合一开关、档位、思考模式、API 展示） |
| `gen_check.py` | 生成 `..\环境检查.bat`（10 项体检） |
| `gen_firewall.py` | 生成 `..\开放局域网端口.bat`（防火墙放行，需管理员） |

### ⚠️ 改 bat 的正确姿势

所有 `.bat` 都是 **GBK 编码 + CRLF 换行**，这是中文 Windows 命令行正确显示中文的前提。
**不要用记事本直接改 bat**（保存时容易被改成 UTF-8，导致中文全部乱码甚至括号解析崩溃）。

正确做法是改生成器再重新生成：

```bash
cd E:\llm-cpp
python _维护脚本\gen_toggle.py
python _维护脚本\gen_check.py
python _维护脚本\gen_firewall.py
```

三个生成器都基于脚本自身位置推导项目根目录，**在任何路径下调用都能正确工作**。

## 三、踩坑记录（改脚本前值得一读）

### 3.1 服务隐藏启动的三要点

服务要在后台**无窗口**运行，用的是「WScript.Shell 的 Run 方法 + 隐藏窗口风格(0) + 不等待(false)」。
这条命令有三个坑，都踩过一遍：

1. **整条 PowerShell 命令只用单引号 + `[char]34` 拼引号**，命令里不出现双引号，
   这样才不会被 cmd 的引号规则搅乱；
2. **`cmd /c` 后面的命令以引号开头时，必须在最外层再包一对引号**
   （脚本里就是 `$q + $q` 那一处）。否则 cmd 会把引号剥掉，命令直接报错、服务根本起不来；
3. **保留 `< nul`**：避免服务持有启动窗口的输入句柄，否则脚本会卡在最后的等待按键上。

另外，PowerShell 里拼接字符串时别多写引号——曾经因为一个多余的单引号，
让整条语句被包进字符串，PowerShell 报「字符串缺少终止符」。
排查这类"看不到输出"的启动失败，可以临时加 `2> "%ROOT%_ps_err.txt"` 捕获 stderr。

### 3.2 用管道喂输入做自动化测试时

Windows 的 `set /p` 从管道读输入有两个坑：

1. **行结束符必须是 CRLF。** 只给 LF（如 `printf '2\n'`）会让换行符混进变量值，
   下一句 `if "%TIER%"==""` 就报「命令语法不正确」并且脚本以 255 退出。
2. **`set /p` 会一次性读走管道里当前可用的全部数据。** 多步交互不能用一次性 `printf`
   喂完，否则后面的 `set /p` 读不到东西，只拿到默认值
   （表现为"明明输入了 y 却仍是 off"）。

正确写法是延迟分隔，模拟真人逐次输入：

```bash
{ printf '2\r\n'; sleep 2; printf 'y\r\n'; sleep 2; printf 'n\r\n'; sleep 2; printf '\r\n'; } \
  | ./启动大模型.bat
```

> 普通用户双击运行不存在这个问题（键盘输入走控制台，逐行读取）。
> 这只影响用脚本 / CI 驱动 bat 的场景。

### 3.3 环境变量可能让 Start-Process 直接报错

`Start-Process` 在环境里同时存在 `HTTPS_PROXY` 与 `https_proxy` 这类**大小写重复**的变量时，
会抛 `ArgumentException`（.NET 的环境变量字典区分大小写）。最终选用 COM 方式启动，
顺带规避了这类环境依赖。

## 四、_历史补丁（可忽略）

`_历史补丁\` 里是历次迭代用过的一次性修补脚本（`patch_*.py`、`fix_*.py`、`update_*.py` 等）。
它们的作用已经固化进当前生成器里，**保留仅为追溯，日常不需要使用，也可以直接删除**。

---

## 五、分发时要不要带这个目录

- **不带**：只影响"以后想改脚本 / 跑基准测试"的能力，不影响服务运行；
- **带**：建议至少保留 `说明.md` 与 `check_deps.py`（后者可在目标机自检依赖）。

分发包的推荐组成见 `..\使用说明.md` 第九章。
